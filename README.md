# 库存管理与 BOM 采购计算器

把 PCB 的 **BOM** 和 **电子料库存表** 自动对上：算出生产 N 套需要买什么、买多少，
同时扣减库存；库存表可通过 GitHub 自动同步，多人共用一份库存。

---

## 1. 文件说明

| 文件 | 作用 |
|---|---|
| `BOM采购计算器.exe` | Windows 双击运行（不需要装 Python） |
| `bom_gui.pyw` | 源码，也可用命令行运行 |
| `bom_vs_stock.py` | 底层比对逻辑（库存充足/不足、待采购、未匹配） |
| `库存管理 副本.xlsx` | 库存表（可替换成你自己的） |
| `电阻电容.md` | 0603 贴片阻容自有清单，命中则免购 |
| `BOM_Board1_PCB1_*.xlsx` | 示例 BOM |

> exe 会以自身所在目录为基准查找 `库存管理 副本.xlsx`、`电阻电容.md`，
> 所以请把 exe 和这两个文件放在同一目录。

---

## 2. BOM 表要求

读取 **第一张工作表**，表头需在前 15 行内；列顺序随意，程序按列名自动识别。

### 必填

| 列名 | 别名 | 说明 |
|---|---|---|
| `Quantity` | 数量 | 每个位号的需求数量。最终需求 = 该值 × 生产套数 |

### 用于匹配库存（至少填一项）

| 列名 | 别名 | 说明 |
|---|---|---|
| `Device` | 器件 / 器件名称 | 如 `AO3400A_C20917` |
| `Manufacturer Part` | 厂商型号 | 如 `AO3400A` |
| `Comment` | 名称 | 如 `AO3400A`、`10uF` |

### 强烈建议保留

| 列名 | 别名 | 说明 |
|---|---|---|
| `Supplier Part` | 供应商编号 | 立创编号 `C20917` 等，匹配最准确 |
| `Footprint` | 封装 | 如 `C0603`，0603 阻容免购判断需要 |

### 可选

| 列名 | 别名 | 说明 |
|---|---|---|
| `Value` | 值 | 如 `10kΩ`、`100nF` |
| `Category` | 分类 | 区分电阻 / 电容 |
| `Designator` | 位号 | 如 `C1,C2`，输出与核对用 |
| `Manufacturer` | 厂商 | 仅作参考 |

### 最小可用示例

| Comment | Quantity | Supplier Part | Footprint |
|---|---|---|---|
| 10uF | 2 | C6119842 | C0603 |
| AO3400A | 3 | C20917 | SOT-23-3 |

> 立创 EDA / 嘉立创导出的 BOM 默认就包含以上全部列，直接使用即可。

## 3. 库存表要求

读取第一张工作表，表头需在前 15 行内。

| 列名 | 必填 | 说明 |
|---|---|---|
| `货品` | ✅ | 物料名称，与 BOM 的型号/名称匹配 |
| `现有库存数量` | ✅ | 当前剩余量，扣减后写回这里 |
| `立创商城商品编号` | 推荐 | 如 `C20917`，匹配优先级最高 |
| `货架` | 可选 | 输出到结果，方便找料 |
| `货品类型` | 可选 | 如电阻、电容 |
| `单价` | 可选 | 不参与计算 |
| `参数简介` | 可选 | 不参与计算 |
| `总计消耗数量` | 可选 | 扣减时自动累加 |

**规则：**

- `现有库存数量` 为 `-1` 视为「充足 / 不计数」，不参与扣减。
- 匹配顺序：立创编号 → 名称完全一致 → 名称包含 → 相似度。
- 多个 BOM 行命中同一货品时，按 BOM 顺序依次分配库存，不会重复使用同一份库存。

## 4. 使用

### 双击 exe

1. 选择 BOM 文件（同目录只有一个 `BOM*.xlsx` 时会自动填入）
2. 填写生产套数
3. 确认库存表
4. 点「开始计算」

输出：`<BOM名>_需采购.xlsx`

- `需采购BOM` 表：只保留还要买的行，**Quantity 已是实际采购缺口**
- `计算明细` 表：每行的需求、库存、可用、扣减、缺口、结论

### 命令行

```bash
python bom_gui.pyw --cli BOM.xlsx --sets 10
python bom_gui.pyw --cli BOM.xlsx --sets 10 --stock 库存.xlsx -o 采购.xlsx
python bom_gui.pyw --cli BOM.xlsx --sets 10 --dry-run     # 只算，不扣库存、不同步
python bom_gui.pyw --cli BOM.xlsx --sets 10 --no-sync     # 扣库存但不同步
```

### 计算规则

- 需求数量 = `Quantity` × 套数
- 库存足够 → 不采购；不足 → 采购缺口部分；库存没有 → 采购全部
- 0603 电阻/电容在库存里查不到，但值在 `电阻电容.md` 里 → 自有（免购）
- 库存表里的 `总计消耗数量` 同步累加

> 部分缺货时，位号不会拆分（例如 3 个位号共需 30 只、库存 28 只，采购 2 只，
> 但采购 BOM 的 Designator 仍列出全部位号）。

## 5. 自动同步到 GitHub（多人协作）

### 前置条件

1. 本目录是从 GitHub **clone** 下来的仓库（含 `.git`，且 `origin` 指向远程）
2. 本机已安装 `git`
3. 已在这台机器完成过一次 GitHub 认证
   （在终端里手动执行一次 `git push`，按提示登录）

### 程序行为

开启同步后（GUI 默认勾选，CLI 默认开启）：

1. **运行前** 自动 `git pull --ff-only`，拿到别人最新的库存
2. **扣减后** 只把库存 xlsx `git add / commit / push`
   （不会提交 BOM、采购结果、备份等本地文件）
3. 推送被拒绝时自动 `git pull --rebase` 再重试
4. 如果 Git 配置的代理连不上，会自动绕过代理重试一次

关闭方式：GUI 取消勾选「自动同步到 GitHub」；CLI 加 `--no-sync`。

### 多人协作约定

- 每个人 clone 同一仓库，用各自的 exe / 脚本指向同一份 `库存管理 副本.xlsx`
- **同一时间只让一个人执行扣减并推送**，避免 xlsx 冲突
- 推送失败时按提示在仓库目录手动 `git pull`，再重新运行
- xlsx 是二进制文件，Git 无法自动合并；冲突时以最后成功推送的版本为准
- 不要把库存表长时间锁在 Excel 里打开，否则保存会失败

## 6. 重新打包 exe

```bash
python -m pip install pyinstaller
python -m PyInstaller --noconfirm --clean --onefile --windowed \
    --name "BOM采购计算器" bom_gui.pyw
```

生成 `dist/BOM采购计算器.exe`，复制到本目录即可。

## 7. 匹配优先级

1. 立创编号完全一致（`Cxxxxxx`）
2. 型号名称归一化后完全一致（去空格、全角转半角、统一大写）
3. 名称包含关系（短名称至少 4 个字符）
4. 相似度 ≥ 0.82（可用 `--threshold` 调整）
5. 前缀 8 位一致且相似度 ≥ 0.72 兜底
